# Repo-map evaluation

The native `mmcg repo-map` command reduced total producer tokens by 6.9% and
uncached input by 12.0% across eight development questions. Tool calls were
essentially unchanged, 292 to 293. This single run does not qualify a general
benefit or a production default.

The [bound measurements](repo-map-20261012.json) retain source inventories,
requested runtime identities, per-attempt usage and answer/result hashes,
failure denominators and unknown values. This is a compact derivative of the
immutable full report identified by its SHA-256.

## Design

One fresh baseline/map attempt per question, alternating condition order. Four
registered benchmark questions and four added repo-map questions retain their
original source revisions. Each pair uses the same frozen source, index, native
binary, tools and base instructions. The candidate adds a 1,600-byte-budget
shortlist and direct-read/uncovered-range instructions to the first prompt.
This measures the bundle, rather than isolating the ranking algorithm.

All sixteen producers completed. Each answer received a fresh condition-hidden
source review requesting GPT 6.1 Sol. Fifteen of sixteen assessments have valid
source anchors. Human reference labels remain pending for all sixteen answers.

The model accepted 6/8 map answers and 5/8 baseline answers, with one baseline
assessment unresolved. The rejected map answers had a citation line offset and
omitted documentation extraction/commit failure behavior. Model assessments are
provisional and use the same requested model family as the producers.

## Accounting and retained evidence

The corrected matrix used 3,863,584 baseline tokens and 3,597,961 map tokens.
An earlier transport revision omitted the native runtime path and produced
sixteen access refusals with zero source calls. Its 617,156 reported producer
tokens are retained as recovery overhead, outside the algorithm comparison.
Including recovery, producer totals are 4,170,386 baseline and 3,908,315 map.
Judge usage is recorded separately; interrupted earlier-review usage can remain
unknown. Served model identity, billing and model rounds are unobserved.

Raw requests, streams, answers, reviews, source/index snapshots and original
reports remain in the local `.mastermind/research/` archive. Their retained paths
and hashes are recorded in the JSON. They are not distributed in this checkout;
reproducing or auditing the original model run requires that archive and the
recorded CLI/runtime bindings. Preserve original records when preparing a new
input revision. Deterministic native tests validate implementation boundaries,
not the semantic quality of model answers.
